# 실제 제출 방법과 최종 체크리스트

작성일: 2026-09-20. 규정은 사용자가 대화에 제공한 신청서 내용을 기준으로 정리했다. 실시간 폼 내용과의 재확인은 제출 직전에 필요하다. 공식 요구와 우리 팀의 권장 준비물을 구분한다.

## 1. 무엇을 제출하는가

**팀 대표 서비스 하나를 정하고, 그 서비스를 설명하는 파일 하나를 Google Form에 업로드한다.** GitHub로 프로젝트를 제출한다면 안내대로 프로젝트명과 링크 주소를 담은 Word/PDF 파일을 올린다. 추천 방식은 **포트폴리오 PDF 1개 + 그 안의 GitHub·데모 영상 링크**다.

| 항목 | 제공된 신청서 기준 | 우리 준비 방식 |
|---|---|---|
| 신청 | 팀 구성원 모두 개별 작성 | 팀명·서비스명·대표 파일은 통일, 개인정보는 본인 작성 |
| 서비스명 | 프로젝트 이름 기입 | SkillForge — 실행 경험을 검증된 업무 절차로 |
| 서비스 파일 | 파일 1개, 최대 1GB | NVIDIA 해커톤_실제팀명_SkillForge.pdf |
| GitHub 링크 제출 | 프로젝트명과 링크를 Word/PDF에 적어 업로드 | PDF 첫 페이지에 클릭 가능한 저장소 링크 |
| Problem | 300자 내외 | 검증된 문제와 대상 사용자 중심 |
| Solution | 500자 내외 | 실제 완성한 핵심 흐름 중심 |
| Tech Stack | NVIDIA 기술과 전체 스택 구체 기재 | 실제 사용 모델·라이브러리·버전·역할 |
| 추가 URL | 선택 | 데모 영상 또는 배포 URL |

3분 영상, 4~6쪽 PDF, GitHub tag는 **우리 팀의 권장 방식**이며 폼에서 확인된 필수 규정은 아니다. 서비스 배포가 반드시 필요하다는 근거는 제공 내용에 없다. 로컬 실행 프로젝트라면 GitHub 재현 가이드와 영상으로 실제 동작을 전달한다. `localhost`나 WSL 경로를 심사자용 배포 URL로 제출하지 않는다.

## 2. 최종 산출물 구조

개발 완료 후 아래 경로를 만든다. 현재 이 경로들의 최종 산출물은 아직 없다.

```text
submission/
  final-form-answers.md       # 최종 서비스명·Problem·Solution·Tech Stack·URL
  portfolio-source.md        # PDF의 수정 가능한 원고
  NVIDIA 해커톤_실제팀명_SkillForge.pdf
  demo-script.md             # 녹화 대본과 장면별 run ID
  manifest.md                # commit/tag, 모델·정책 버전, 링크, 검토일
artifacts/eval/<evaluation-id>/
  manifest.json
  summary.json
  report.md
docs/reviews/
  milestone-*.md             # 개발 보고 및 검토 결과
```

제출 확인 화면에는 개인정보가 포함될 수 있으므로 공개 저장소에 넣지 않고 개인 보관한다. PDF에는 API 키, 계정 인증 정보, 불필요한 개인 연락처를 넣지 않는다.

## 3. PDF는 이렇게 구성한다

1. **첫 페이지:** 서비스명·팀명·한 문장 가치·대표 화면·GitHub와 영상 링크. 심사자가 바로 무엇을 만들었는지 알게 한다.
2. **문제와 사용자:** 반복 환불 업무의 불편, 현재 방식, 합성 환경으로 검증한 범위. 인터뷰가 없으면 고객 검증 완료라고 쓰지 않는다.
3. **서비스와 흐름:** ReAct 실행 → 기록에서 후보 유도 → 별도 검증 → 운영자 활성화 → 재사용. 화면과 짧은 설명을 붙인다.
4. **기술과 NVIDIA:** 실제 모델명, NAT 사용 지점, MCP, 직접 구현한 컴파일러·정책 검사. 격리는 실제 검증된 경우만 포함한다.
5. **결과와 한계:** A/B/C 실측표, 표본·조건, 중복 환불/정책 변경 차단 사례, 남은 제약. 숫자마다 report 또는 run ID를 연결한다.
6. **재현과 참고:** 실행 순서, 필요한 키, live/mock 구분, 선행 연구와 출처. 분량이 적으면 5쪽과 합친다.

긴 코드나 로그 원문으로 페이지를 채우지 않는다. PDF만 봐도 가치와 근거가 이해되고, 자세한 구현은 저장소로 연결되도록 한다. PDF를 만든 뒤 전체 페이지를 렌더링하거나 열어 잘림·한글 깨짐·클릭 링크를 확인한다.

## 4. GitHub·영상 준비

- README 첫 화면에 서비스 설명, 실행 화면, 데모 영상, 재현 방법을 둔다.
- 설치 명령은 새 환경에서 실제로 검증한다. Python/Node/패키지 버전과 필요한 환경변수의 **이름**을 적는다.
- live에는 사용자 본인의 NVIDIA API 키가 필요함을 밝히고, 키 없이 확인할 mock 모드를 따로 안내한다.
- 실측 report와 개인정보를 제거한 증거를 남긴다. mock 데이터를 live 결과로 표시하지 않는다.
- 최종 commit SHA를 manifest에 남기고, Git을 사용한다면 선택적으로 제출 tag를 고정한다.
- 심사자가 접근할 수 있는 링크인지 로그아웃 상태에서 확인한다. 비공개 저장소라면 주최 측의 접근 방식이 확인되어야 한다.
- 영상은 정상 처리, 후보 생성/검증/재사용, 예외 차단, 실측 비교를 담는다. 녹화·재생은 그대로 표시한다.
- 외부 게시·저장소 공개 전환·배포는 사용자가 최종 범위를 정해 실행한다. 개발 에이전트는 먼저 검토 가능한 산출물을 준비한다.

## 5. Google Form 작성 순서

1. [공식 신청서](https://docs.google.com/forms/d/e/1FAIpQLScyZ5GYYaCOycNUzXVUTenliEUmSEIdXelVdYphvMvLeLuiHA/viewform)를 연다. 사용할 Google 계정을 본인이 확인한다.
2. 신청 자격·팀 구성·일정을 읽고 필수 개인정보 동의를 본인이 선택한다. 선택 마케팅 동의와 구분한다.
3. 폼에 표시되는 개인·팀 정보를 입력한다. 성명, 연락처, NVIDIA 계정 이메일, GitHub ID는 각자 실제 정보로 작성한다. 이 문서가 확인하지 못한 필드 순서나 선택지는 현행 폼을 따른다.
4. Section 02에 통일된 서비스명을 입력한다.
5. 최종 PDF 1개를 업로드하고 업로드 완료·파일명을 확인한다. GitHub URL만 붙여넣고 업로드를 누락하지 않는다.
6. `submission/final-form-answers.md`에서 Problem, Solution, Tech Stack을 복사한다. 초안의 “계획입니다”를 일괄 치환하지 말고 실제 완료 상태로 다시 작성한다.
7. 추가 URL이 있으면 입력한다. PDF에 들어간 링크와 일치하는지 확인한다.
8. 전체 일정과 추가 동의 내용을 각자 읽는다. 필수/선택은 현행 폼 표시를 따른다.
9. 제출 직전에 팀명·프로젝트명·파일·링크·개인정보·동의 선택을 확인하고 본인이 제출한다.
10. 완료 화면 또는 접수 확인 메일이 있으면 개인 보관한다. 모든 팀원이 각각 완료했는지 팀 내부에서 확인한다.

## 6. 날짜와 미확정 사항

제공된 접수 종료일은 **2026-09-28**이다. 마감 시각은 확인되지 않았으므로 23:59라고 가정하지 않는다. 9/27 내부 완료를 목표로 잡는다. “Skill API”의 정확한 의미와 증빙 요건은 T00의 필수 확인 항목이다. 팀원 모두 신청하라는 안내에 따라 공통 포트폴리오를 준비하되, 팀원별 파일 업로드 요구는 현행 폼에서 확인한다.

## 7. 최종 제출 게이트

- [ ] 팀명·2~5인 구성·각 팀원 신청 준비 확인.
- [ ] Skill API 요구와 충족 증거 확인. 미확인이면 제출 적합 판정은 보류.
- [ ] 대표 서비스가 실제로 실행되며 핵심 데모를 재현할 수 있음.
- [ ] 중복 환불·승인 우회·쓰기 후 오류의 미해결 중대 결함 없음.
- [ ] 실측 수치와 원본 run/report가 일치하고 제한 사항이 기재됨.
- [ ] NVIDIA 사용 기술 목록이 실제 구현과 일치함.
- [ ] 제출용 PDF 열림·한글·페이지·링크 검수 완료, 파일 1개/1GB 이내.
- [ ] 최종 문구 분량 확인, 계획과 완료 사실 혼동 없음.
- [ ] GitHub/영상 접근 확인, localhost URL과 비밀정보 없음.
- [ ] 현재 마감 시각 및 폼 변경 사항 확인.
- [ ] 최종 검토 결과 기록 후 각 팀원 직접 제출.

검토 결과는 “제출 준비 완료 / 수정 후 재검토 / 증거 부족”으로 남긴다. 이는 팀의 준비 판정이며 주최 측의 접수·심사 통과 보장은 아니다.
