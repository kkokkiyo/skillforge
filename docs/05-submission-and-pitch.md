## 서비스명

**SkillForge — 실행 경험을 검증된 업무 절차로**

팀명: 미정. 파일명: `NVIDIA 해커톤_팀명_SkillForge.pdf` 또는 `.docx`.

## Problem Definition 초안 (약 300자, 공백 포함)

커머스 고객지원에서는 반품 확인과 환불처럼 같은 절차가 반복됩니다. 범용 AI 에이전트는 매 요청마다 주문, 반품 상태, 정책을 다시 해석하며 여러 차례 모델을 호출합니다. 고정 자동화는 빠르지만 절차를 사람이 작성하고 정책 변화에 맞춰 관리해야 합니다. 운영자는 어떤 근거로 환불했는지, 재사용한 절차가 현재 정책에도 유효한지 확인하기 어렵습니다. 우리는 반복 업무의 추론 비용과 실행 불투명성을 줄이고자 합니다. 합성 주문 환경에서 정상 환불, 승인 대기, 중복 요청과 정책 변경을 재현해 이 문제와 해결 가능성을 검증할 계획입니다.

## Solution 초안 (약 500자, 공백 포함)

SkillForge는 에이전트의 성공한 실행 기록에서 반복 절차를 찾아 검증 후 재사용하는 운영 콘솔입니다. 처음 접한 환불 요청은 Nemotron 기반 에이전트가 주문·반품·정책을 조회하며 처리합니다. 시스템은 도구 호출 순서와 입력값의 출처를 기록하고, 같은 절차가 반복되면 실행 가능한 선형 워크플로 후보를 만듭니다. 후보는 생성에 사용하지 않은 정상·예외 사례로 검증하며 운영자가 활성화한 뒤 새 요청에 적용합니다. 모든 환불은 공통 정책 검사를 거치고 고액 건은 별도 승인을 요구합니다. 중복 요청, 변경된 정책, 실행 결과가 불확실한 오류는 재실행 전에 차단하거나 확인합니다. 콘솔에서는 후보의 원본 기록, 검증 결과, 승인·차단 이유를 추적할 수 있습니다. 일반 에이전트, 수동 절차, 자동 생성 절차를 같은 조건에서 비교해 성공률과 모델 호출·지연을 평가할 계획입니다. 실제 결제 대신 모의 주문 시스템으로 재현 가능한 데모를 제공합니다.

## 심사 질문에 대한 답변

**왜 그냥 수동 workflow가 아닌가?** 단일 환불 업무에는 수동 절차도 적합합니다. 그래서 비교군 B로 포함했습니다. 우리는 업무 실행에서 후보를 찾고 출처·검증·버전 관리를 연결하는 과정을 구현했습니다. 작성 시간 절감은 측정한 경우만 주장합니다.

**어디까지 자동인가?** 도구 순서 그룹화와 타입이 확인되는 인자 참조 유도는 자동입니다. 업무 계약·정책·지원 범위는 사람이 정의하고 활성화도 운영자가 합니다.

**NVIDIA가 왜 필요한가?** Nemotron이 처음 요청의 도구 선택과 의도 해석을 수행하고, NAT로 실행·측정 근거를 연결합니다. OpenShell을 실제 연결한 경우에만 하위 실행 격리를 설명합니다. 다른 모델로 대체 불가능하다고 주장하지 않습니다.

**안전한가?** 모의 환경의 명시된 사례에서 불변식과 차단 결과를 검사했습니다. 작은 평가에서 위반 0건은 일반 안전 보장이 아닙니다. 실제 결제·인증·장애 복구는 별도 검증이 필요합니다.

**기존 연구와 무엇이 다른가?** 경험에서 workflow를 얻는 방향은 기존 연구에 있습니다. 우리의 범위는 커머스 변경 작업의 인자 출처, 검증 승격, 정책 무효화, 실행 증거를 하나로 연결한 프로토타입입니다.
