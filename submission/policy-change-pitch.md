# 3분 데모: 검증한 자동화도 정책이 바뀌면 다시 확인해야 합니다

0:00-0:25 문제: 환불 업무는 반복적이지만 정책은 변합니다. 운영자는 빠른 처리뿐 아니라 자동화를 계속 믿어도 되는지 알고 싶습니다.

0:25-0:55 실행: 실제 Nemotron trace와 source mode를 보여 줍니다. 6개 업무 도구와 DB oracle를 확인합니다. 모델이 승인 권한을 갖지는 않습니다.

0:55-1:20 생성: 서로 다른 주문 5건의 실제 출처를 참조로 바꿉니다. 지원 범위는 정해진 6단계 환불 절차입니다. 분리된 validation 30건 + 경계 6건을 확인하고 활성화합니다.

1:20-2:05 변화: 승인 기준 50만원 → 30만원 미리보기. 35만원 환불은 이전 자동 처리, 이후 승인 필요입니다. 42쌍의 합성 비교에서 바뀐 판정과 오차단·위험 변경을 보여 줍니다. 아직 운영 주문에는 변화가 없습니다.

2:05-2:35 재승격: 정책 적용 → 기존 절차 STALE → 부모 출처를 가진 새 후보 → 재검증 → 운영자 활성화. 새 35만원 주문이 승인 대기하고, 승인 후 1회만 환불되는 것을 보입니다.

2:35-3:00 가치·한계: 워크플로 메모리와 사람 승인 자체는 선행 기술입니다. SkillForge는 출처·변경 영향·재검증을 하나의 운영 판단으로 연결합니다. 실제 결제·산업 일반화·OpenShell 격리·대회 Skill API 요구 충족은 주장하지 않습니다.
